AgriQL queries and AgriCUDA computing.

APSInsight does not keep farm records alone. It uses AgriQL to ask questions of those records, and AgriCUDA to check and run a calculation. Both are ASPF languages. This page says what that support is. It does not accept a query or a program, and it does not print their source.

AgriQL — the query language

AgriQL is the agricultural query language and database APSInsight is wired to: engine 3.10.1, grammar 1.0. A question can be asked of the catalogue of measurements rather than of a spreadsheet whose units were forgotten.

Support in APSInsightWhat it means for a farm record
CatalogueSee which schemas and tables the engine is holding.
Select and aggregateAverage, count, minimum, maximum, and spread, with a filter and a group. Example: the average pH of samples from one field, if those samples were recorded.
Unit conversionA depth or a rate can be converted between declared units, so millimetres are not silently read as inches.
CSV importA table can be filled from a CSV file. This website does not offer that upload.
ProfileA table can be profiled so an empty or odd column is visible before someone trusts it.
ProvenanceAPSInsight keeps the query together with its result. The number can be traced back to the question that produced it.

A point type for a place exists in AgriQL. That is not a finished map inside APSInsight, and this site does not draw one.

AgriCUDA — the computing language

AgriCUDA is an agriculture-oriented language for calculation. APSInsight can ask AgriCUDA to check a program, and to run it. A check covers types and the rules for parallel work. A run compiles the program to bytecode and executes that bytecode on the CPU. A second reading of the same program must agree. If the two readings disagree, the run fails rather than returning a quiet wrong number.

  • The device APSInsight uses is the CPU. Work is done in order on that device. It is not a graphics processor.
  • A GPU backend is not implemented.
  • An FPGA backend is not implemented.
  • Writing a native object file is not implemented. Checking and running are.
  • The kind of farm arithmetic the language is used for includes a degree-day total and a soil-water balance. Those are examples of the language, not a recommendation for a plot, and this page does not publish a sample result as advice.

When the language is not installed

APSInsight looks for the real AgriQL engine and the real AgriCUDA program. If either one is absent, the platform says so. It does not invent rows, and it does not invent a calculation. A label that a stand-in was used is not a field measurement.

Questions

What is AgriQL in APSInsight?

AgriQL is ASPF’s agricultural query language, engine 3.10.1 and grammar 1.0, used by APSInsight. It can show the catalogue, select and aggregate measurements, convert units, import a CSV into a table, and profile a table. The query is kept with its result.

What is AgriCUDA in APSInsight?

AgriCUDA is ASPF’s agricultural computing language. APSInsight can check a program and run it on the CPU. The run is a real execution, not a picture of a result. Degree-day accumulation and a soil-water balance are examples of the kind of calculation the language is for.

Does AgriCUDA use a GPU?

No. AgriCUDA’s current device is the CPU. A GPU backend, an FPGA backend, and a native object-file build are not implemented. APSInsight does not claim them.
