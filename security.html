Tenant first, then role.

Other tenants look like they are not there. This page states controls that have tests, and the residual risk that remains. It does not publish exploit steps.

What is protected

  • Tenant records and their history.
  • The hash-chained audit log.
  • API tokens, stored only as SHA-256.
  • Schemas, rules, workflows and other operational metadata.

Controls that have tests

  • The tenant comes only from the token. A cross-tenant read returns not-found, so identifiers cannot be probed.
  • Roles are a fixed ladder: viewer, editor, admin, plus auditor. Restore, delete, legal hold, schemas and migrations need the higher roles.
  • Tokens are never logged in the clear. Metrics labels are slugs and codes, not record contents.
  • Mutations validate before they write. A failed operation leaves no record change, only an audit event.
  • The journal is fsynced per commit. Snapshots are written atomically. The audit chain is verified on open.
  • Planned device commands must name an actuator, require acknowledgement and an interlock, and expire. No device adapter is reachable in this build.

Residual risk, stated plainly

  • Static tokens rotate by restart. There is no revocation list, so a leaked token works until the process is restarted.
  • The rate limit is per process. Several replicas would not share one counter.
  • Anyone with filesystem access to the data directory is fully trusted. The server does not terminate TLS; an operator proxy does.
  • Anonymisation is not implemented. Records may contain personal data about farmers or workers. Keep the minimum, and delete only archived records that are not on legal hold.
  • Release artifacts are not signed yet. The product is pre-1.0. Only the latest commit on main receives security fixes.

This website

  • Static files only. No JavaScript, no cookies, no forms, no analytics, no third-party requests.
  • Content-Security-Policy is default-src 'none' with styles and images limited to this origin. Inline scripts and eval are not permitted.
  • Pages are served over HTTPS by GitHub Pages. Transport headers such as HSTS are set by GitHub, not by this repository.
  • The repository has no application secrets. Push protection and private vulnerability reporting are enabled.
  • Direct force-push and deletion of main are rejected by a repository ruleset.

Reporting

  • Engine defects: use Security → Report a vulnerability on SbruiceS/APSInsight. Do not open a public issue. There is no bug bounty. Acknowledgement is aimed at within 3 working days.
  • Defects in this public site: email sbruicesingh@haclon.in or use private vulnerability reporting on this repository. See security.txt.
